# Preparação e limitações de captura — 15/11/2026

Registro de observações da sessão. As primeiras tentativas ocorreram antes da criação do capturador: os trechos abaixo são transcrições das saídas retornadas pelas ferramentas, **não logs originais completos**. Seus horários individuais não foram preservados em arquivos e não são inventados. Logs posteriores possuem horários reais nos cabeçalhos.

1. `composer install --no-interaction --prefer-dist` no sandbox: falha de conexão ao Packagist (curl error 7), cache externo sem permissão de escrita e ausência de ZIP/unzip no PATH. A repetição autorizada com acesso de rede continuou bloqueada por ZIP desabilitado. Saída: `The zip extension and unzip/7z commands are both missing, skipping.`
2. A DLL `C:/xamppApp/php/ext/php_zip.dll` já estava disponível. Instalou-se o lock com `php -d extension=zip C:/ProgramData/ComposerSetup/bin/composer.phar install --no-interaction --prefer-dist`, sem alterar php.ini. O Composer resolveu **109 instalações, zero atualizações, zero remoções**, concluindo o autoload e a descoberta de pacotes. As execuções PHPUnit posteriores comprovam o ambiente funcional. Nenhum lock foi alterado.
3. `node`, `docker` e `py` não foram localizados no PATH. `python` apontava para WindowsApps e sua execução foi recusada. Foram encontrados Python 3.13.18 e uv existentes no perfil local; nenhuma instalação global foi necessária. `uv python list --only-installed` inicialmente falhou ao abrir cache `.lock` fora do workspace. Foi utilizado `--cache-dir .tools/uv-cache` e criado `python-api/.venv` com os pins de requirements.txt.
4. Node 24.22.3 portátil foi baixado do domínio oficial nodejs.org. O SHA256 do ZIP foi comparado com a linha win-x64.zip de SHASUMS256 oficial antes da extração. Arquivos ficam em `.tools/`, ignorado. `npm ci` concluiu com 457 pacotes; veja `npm-ci.log`. Chromium/FFmpeg/Winldd foram instalados pelo Playwright; veja `chromium-install.log`. O Python recebeu pypdf 7.1.0 apenas para extração do PDF, sem mudança em requirements.txt.
5. A execução inicial dos scripts ps1 foi recusada pela política local (`PSSecurityException`). Repetiu-se com `Set-ExecutionPolicy -Scope Process Bypass -Force`: só o processo atual foi ajustado. Não houve mudança global de política. O capturador registra o código de saída, inclusive quando a suíte falha.
6. Extração do PDF: uma tentativa de Python `-c` falhou por aspas no PowerShell; passou-se a arquivo de script local. Uma segunda tentativa gravou o texto UTF-8, mas a impressão no terminal cp1252 falhou por caractere não representável. O arquivo salvo foi lido integralmente com `Get-Content -Encoding UTF8`, confirmando equipe e histórias US01–US20. O arquivo `sprint-1-extraida.txt` contém a extração real, inclusive espaçamento original do PDF.
7. Consulta ao nome comercial do Windows por CIM recebeu `Acesso negado`. O relatório usa Windows/PowerShell observados e não inventa edição do SO.
8. Reteste intermediário do formulário: a adaptação usou `getByLabel`, método inexistente do renderizador Vitest, causando três falhas. A declaração local da API confirmou `getByLabelText`; correção restrita ao teste foi seguida de nova execução com seis aprovações. Saídas integrais em `frontend-reteste-formulario.log` e `frontend-reteste-formulario-2.log`; INC-002.
9. Durante a consolidação, o leitor do JUnit inicialmente esperava separadores de namespace em barra invertida, mas o XML do PHPUnit utiliza pontos. O leitor foi corrigido antes de gerar o inventário; a validação posterior conferiu a existência de cada arquivo listado. Uma tentativa de patch com exclusão e inclusão do mesmo arquivo foi recusada sem alterar o arquivo, e refeita como atualização única. Essas ocorrências não são falhas da aplicação.
10. O validador documental inicial exigiu conteúdo direto antes da primeira subseção de um título pai e rejeitou `1. PLANO DE TESTE`. Corrigiu-se a regra para verificar o conteúdo completo da seção, incluindo subseções. `validacao-inicial.log` preserva a falha do validador, e `validacao-2.log` registra a aprovação após a correção. Essa aprovação não modifica os vereditos dos testes do produto.

O Docker não foi preparado nem executado com sucesso. `docker.log` registra a tentativa e o bloqueio atual. Não se infere funcionamento de MariaDB, de daemon Docker ou de volumes a partir das aprovações SQLite.

Os logs capturam texto de stdout/stderr pelo PowerShell, que pode inserir `System.Management.Automation.RemoteException` em linhas vazias de stderr. JSON e JUnit foram preservados para conferência estruturada. Nenhuma saída de token, segredo pessoal ou resposta fictícia foi usada como evidência.
